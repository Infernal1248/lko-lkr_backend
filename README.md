# Реестр — backend

Laravel 13 API для сервиса личных карточек работников. Целевая версия PHP: **8.4.25** (зафиксирована в Composer platform и Dockerfile). Интерфейс Vue 3 находится в соседнем репозитории `lko-lkr_frontend`.

## Локальный запуск

Требуются PHP 8.4.25+, Composer, расширения curl, dom, fileinfo, GD с FreeType, mbstring, zip, xml, intl и драйвер выбранной БД (pdo_mysql для MySQL, pdo_pgsql для PostgreSQL, pdo_sqlite для SQLite). Предпросмотр формируется непосредственно в PHP GD; Poppler, внешние команды и VPS не обязательны.

```sh
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
php artisan serve --host=127.0.0.1 --port=8000
```

Укажите `APP_URL=http://127.0.0.1:8000`. В отдельном frontend-проекте выполните `npm ci && npm run build`: результат останется в его каталоге `dist`. Для текущей схемы раздачи через Laravel содержимое готового `dist` размещается в `public/app` отдельным шагом развёртывания, а не командой сборки. Затем откройте http://127.0.0.1:8000.

Для разработки Vue можно запустить его dev-сервер, который проксирует API в Laravel. API использует same-origin сессии Laravel и CSRF. Не храните токены доступа в localStorage.

Локальные демонстрационные данные (только `APP_ENV=local/testing`):

```sh
php artisan db:seed --class=LocalDemoSeeder
```

Аккаунт: `demo@example.test`, пароль: `DemoOnly-2026-Password`. 25 тестовых генераций, условный сотрудник и профиль принтера. Не переносите демонстрационную БД в production. Для своего локального аккаунта: `php artisan cards:demo email@example.com --credits=10`.

## Реализовано

- Регистрация, вход, выход, восстановление пароля через Laravel Notifications; SMTP задаётся в `.env`.
- Подтверждение полномочий работодателя с версией текста и организацией.
- Реквизиты организации, картотека, CSV/XLSX импорт до 500 строк (UTF-8 CSV; заголовки `фамилия;имя;отчество`). Импорт атомарный.
- Реестр сгенерированных карточек с поиском по ФИО, пагинацией, бесплатным повторным скачиванием и удалением PDF/персональных данных.
- Серверный PDF A5 210 × 148 мм, только чёрный текст; встроенный Liberation Serif Bold, 10–14 пт. Выход за размер строки блокирует генерацию.
- Серверный PNG-предпросмотр через GD/FreeType с водяным знаком; общий с PDF расчёт координат и размеров, без запуска внешних программ и временного PDF.
- Профили принтеров, поправки X/Y и отдельных строк, бесплатный тест с фиксированными данными.
- Пакеты генераций, ЮKassa redirect checkout, проверяемые уведомления, журнал баланса, защита от повторной оплаты/списания одного запроса.
- Основное размещение: обычный PHP-хостинг REG.RU, PHP 8.4.25 и MySQL 5.7.44. VPS и постоянный worker не требуются.

## Печать и шаблоны

`config/cards.php` содержит закрытые координаты бланка, версию, производителя, формат, путь к образцу и тарифы. Активны `ppd-lkr` и `ppd-lko` (ООО «Первый печатный двор»); для каждой серии отдельные координаты, подложка и профили печати. Добавление производителя не требует изменения учёта генераций. Новая серия с другими полями потребует расширения `CardInput` и формы.

Для ЛКР используется скан `img-261006083416-001.pdf`, для ЛКО — `img-261006083337-001.pdf`. Полные изображения и фрагменты для калибровки находятся в `resources/templates/ppd-{lkr,lko}*.png`. Исходная страница А5 приведена к альбомной ориентации. Реальный PDF содержит **0 изображений**, 1 страницу 210 × 148 мм, встроенный LiberationSerif-Bold. Изготовитель бланка и скан не являются реквизитами оператора сервиса.

Поля измерены по скану. До коммерческого использования обязательна физическая пробная печать на исходном А5 при 100%, затем проверка на специальном бланке. Поля под обрезку учитываются относительно исходного листа. Размер шрифта автоматически уменьшается с выбранного до 10 пт; текст, который не помещается, нужно сократить. Никаких шрифтов с внешнего CDN.

`resources/fonts/LICENSE.txt` — SIL Open Font License, права на Liberation Fonts. Исходный TTF и подготовленные метрики/подмножества включены в репозиторий, запись в vendor при генерации не требуется.

## Баланс и идемпотентность

`POST /api/generations` принимает UUID `request_key`. Транзакция блокирует пользователя, проверяет прежний запрос, создаёт PDF, сохраняет зашифрованный файл и неизменяемый снимок, затем списывает 1 единицу и добавляет запись журнала. Ошибка откатывает всё. Повтор с прежними данными возвращает ту же генерацию; тот же ключ с другими данными — 409. Скачивание не меняет баланс.

PDF и снимок сохраняются зашифрованными в БД вместе с транзакцией. Это устраняет рассогласование файлового хранилища и баланса, но увеличивает размер БД; резервное копирование и свободное место должны учитывать PDF. ФИО черновиков и реквизиты также зашифрованы Laravel Crypt. Сохраните `APP_KEY` отдельно: его потеря означает потерю доступа к зашифрованным данным. Шифрование не заменяет контроль доступа, HTTPS и защиту резервных копий.

Поиск по зашифрованным ФИО выполняется сервером через cursor с расшифровкой только записей текущего аккаунта. Для очень больших реестров потребуется отдельное проектирование защищённого поискового индекса; сейчас сложность поиска линейная.

## ЮKassa

По умолчанию `PAYMENTS_ENABLED=false`. Для тестового магазина задайте:

```dotenv
PAYMENTS_ENABLED=true
YOOKASSA_SHOP_ID=...
YOOKASSA_SECRET_KEY=...
YOOKASSA_TEST=true
YOOKASSA_VAT_CODE=1
APP_URL=https://your-domain.example
```

Webhook: `POST https://your-domain.example/api/payments/webhook`, событие `payment.succeeded` (также можно `payment.canceled`). Исключение CSRF действует только на этот endpoint. Содержимое уведомления не является подтверждением оплаты: сервер получает платёж по API с учётными данными магазина и сверяет ID, order_id, сумму, валюту, paid и test mode. Повтор webhook безопасен. Если уведомление не поступило, статус оплаты можно проверить вручную в личном кабинете. Cron и запуск планировщика для работы сервиса не требуются.

Цена и количество берутся из серверного каталога. Клиент их изменить не может. Для самозанятого используется `YOOKASSA_RECEIPT_MODE=npd_manual`: платёж создаётся без 54-ФЗ receipt. ЮKassa прекратила автоматические чеки НПД 29.12.2025. Для отдельного режима `54fz` требуется подключённая совместимая касса; он не заменяет чек НПД. Перед приёмом настоящих денег утвердите тарифы в `config/cards.php`, настройку чеков, замените рабочие юридические тексты и установите `YOOKASSA_TEST=false` с реальными ключами. Реальные платежи и магазин не проверялись; автоматические тесты используют подменённые ответы API и не расходуют деньги.

При неизвестном результате создания платежа повтор использует тот же идентификатор. После 23 часов незавершённый запрос без provider_id блокируется для ручной сверки, чтобы не создать второй платёж после истечения окна идемпотентности провайдера.

## Хранение

PDF и снимок данных хранятся до удаления пользователем. Повторное скачивание бесплатно и не ограничено сроком. Автоматическая очистка по возрасту отключена; миграция удаляет прежнее поле expires_at, сохраняя файлы и записи реестра.

Публичная политика открывается по `/?page=privacy` без авторизации. Реквизиты владельца задаются `SERVICE_OPERATOR_NAME`, `SERVICE_OPERATOR_INN`, `SERVICE_PRIVACY_EMAIL`, `SERVICE_OPERATOR_ADDRESS`. Регистрация фиксирует ознакомление с версией политики. При каждой передаче данных требуется `data_rights=true`; подтверждение работодателя не подменяет согласие работника и не снимает обязанностей владельца сервиса.

## Развёртывание

На обычном PHP-хостинге: используйте PHP 8.4+, GD с FreeType и pdo_mysql. Укажите реквизиты MySQL в `.env`, production/HTTPS-настройки и SMTP; направьте корень сайта в `public`. Выполните `php artisan config:clear`, `php artisan migrate --force`, `php artisan config:cache`, `php artisan route:cache` подходящим PHP CLI. Старую переменную `PDFTOPPM_BINARY` можно удалить: она больше не используется. Фактические расширения и работу MySQL нужно проверить на сервере хостинга.

После обновления сделайте резервную копию БД и APP_KEY и выполните подходящим PHP CLI:

```sh
/opt/php/8.4/bin/php artisan migrate --force
/opt/php/8.4/bin/php artisan cards:link-employees
/opt/php/8.4/bin/php artisan support:admin kochergin.vladim@mail.ru
/opt/php/8.4/bin/php artisan config:cache
/opt/php/8.4/bin/php artisan cards:check-hosting
```

Для назначения администратора сначала зарегистрируйте этот email на сайте. Команда не создаёт аккаунт и не меняет пароль. `support:admin email --revoke` снимает права. Администратор видит очередь обращений и раздел «Чеки НПД». Обычный пользователь видит только свои обращения и покупки.

`cards:link-employees` связывает существующие документы с единственным точно совпадающим сотрудником либо создаёт сотрудника. Команда повторяема; PDF и баланс не изменяются. Для новых PDF сотрудник создаётся в той же транзакции. Старые профили принтера нужно завершить через калибровку: `calibrated_at` ранее не фиксировалось.

Для боевой оплаты установите `PAYMENTS_ENABLED=true`, `YOOKASSA_TEST=false`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET` реального магазина, `APP_URL=https://ваш-домен` и webhook `https://ваш-домен/api/payments/webhook` для `payment.succeeded` и `payment.canceled`. Не переносите тестовую БД/тестовый баланс в production. После смены env сбросьте и пересоберите конфигурацию. Проверьте один платёж и его единственное зачисление. Ключи хранятся только на сервере.

В режиме `npd_manual` оплаченные реальные заказы появляются в разделе администратора «Чеки НПД», вместе с типом плательщика, ИНН, email, суммой и датой. Создайте чек в «Моём налоге» в срок, установленный законом, прикрепите его официальную ссылку: покупатель получит доступ к ней в истории оплаты. Прикрепление ссылки не отправляет сведения в ФНС и не доказывает выдачу чека. Автоматизация требует договора и API действующего уполномоченного партнёра ФНС; не используйте неофициальный вход по паролю в «Мой налог».

Источники: [изменения API ЮKassa, объявление 23.12.2025](https://yookassa.ru/developers/using-api/changelog), [ФНС о формировании чеков самозанятыми](https://www.nalog.gov.ru/rn53/news/activities_fts/16643640/).

Реестр: `PUT /api/generations/{id}/registry`, выгрузка `GET /api/registry/export/pdf` или `/xlsx`, параметр `q` повторяет поиск по ФИО/номеру. Дополнительные поля необязательны. Полнота включает номер бланка, кадровые сведения и удостоверение для охранника. PDF — А3 альбомный с повторяющейся шапкой, XLSX сохраняет начальные нули и не исполняет формулы. Лимит выгрузки — 2000 строк после фильтрации. Изменение реестра не изменяет исходный PDF и карточку сотрудника; списания нет.

Поддержка работает обычными HTTP-запросами с обновлением ответа кнопкой, без WebSocket и постоянного фонового процесса. Новые миграции не используют возможности MySQL 8. Фактический запуск на MySQL 5.7.44 и PHP 8.4.25 на хостинге ещё нужно проверить; локальная среда использует PHP 8.5.10 и SQLite.

## Проверки

```sh
php artisan test --compact
composer audit
vendor/bin/pint --dirty --format agent
```

Покрыты баланс, идемпотентность, отказ генератора, изоляция пользователей, шрифт/переполнение, поиск/хранение/удаление, бесплатная калибровка, CSV/XLSX, профили, вход/выход/сброс пароля, повторные и поддельные уведомления, серверные цены. Реальный HTTP POST без CSRF возвращает 419. Браузерный сценарий вход → предпросмотр → генерация → реестр → поиск → скачивание проверен на условных данных.

Номер физического бланка закрепляется после печати через `PUT /api/generations/{id}/number`, не входит в PDF и не расходует генерации. Хранится зашифрованно, начальные нули сохраняются; HMAC и уникальный индекс предотвращают повторное назначение номера одной серии в кабинете. Реестр ищет по ФИО или номеру. Передайте `card_number: null`, чтобы снять закрепление.

Пробная печать: `proof=true` у `/api/calibration/pdf` возвращает А4 (210 × 297 мм) с двумя бланками 210 × 148 мм. Резать на отметках 148 и 296 мм; нижний остаток 1 мм удалить. Данные печатаются отдельным PDF А5. Масштаб в обоих случаях 100%.

ЮKassa: `PAYMENTS_ENABLED=true` включает приём оплаты. Основное имя ключа — `YOOKASSA_SECRET_KEY`; прежнее `YOOKASSA_SECRET` поддерживается как запасное. После изменения `.env` выполните `php artisan config:cache`. Наличие реквизитов не проверяет их действительность: проведите тестовый платёж. Тарифы редактируются администратором в разделе «Тарифы»: название, количество генераций, цена, доступность и порядок. Миграция `2026_10_13_000001_create_packages` однократно переносит пакеты из `config/cards.php` (включая `PACKAGE_50_AMOUNT`, если он задан). После миграции источником тарифов становится база данных; изменение конфигурации больше не меняет цены. Использованные тарифы можно отключать; существующие заказы сохраняют сумму и количество генераций. При обновлении выполните `php artisan migrate --force` до публикации нового фронтенда.

## Push-уведомления

Пользователь получает уведомление об ответе поддержки. Все аккаунты с правами
`support:admin` получают уведомления о новых обращениях, новых сообщениях пользователей
и впервые подтверждённых оплатах. Повторный webhook не создаёт повторное уведомление.
Тестовые оплаты явно помечены; чек НПД для них не требуется. Нажатие открывает
обращение либо раздел чеков (после входа, если сессия закончилась).

Настройка на REG.RU после обновления обоих проектов:

```sh
/opt/php/8.4/bin/php ~/bin/composer install --no-dev --prefer-dist --optimize-autoloader --no-interaction
/opt/php/8.4/bin/php artisan migrate --force
/opt/php/8.4/bin/php artisan push:keys
```

`push:keys` выполняется однократно: записывает VAPID-ключи прямо в серверный `.env`,
не выводит секреты и не изменяет APP_KEY. Если ключи уже есть, команда откажется
перезаписывать их. Сохраняйте эти ключи при обновлении сайта: смена ключей требует
повторного подключения браузеров. Установите в `.env`:

```dotenv
PUSH_ENABLED=true
VAPID_SUBJECT=mailto:kochergin.vladim@mail.ru
```

Затем:

```sh
/opt/php/8.4/bin/php artisan config:cache
/opt/php/8.4/bin/php artisan cards:check-hosting
```

Фронтенд: `npm ci && npm run build`, загрузить содержимое **frontend/dist** в
**backend/public/app**, включая `push-sw.js`, `manifest.webmanifest` и иконки.
Laravel отдаёт service worker по `/push-sw.js` с областью действия `/` —
это также нужно для приложения с экрана «Домой». Не подменяйте этот адрес HTML-страницей.
Если вашему аккаунту ещё не выданы права администратора:

```sh
/opt/php/8.4/bin/php artisan support:admin kochergin.vladim@mail.ru
```

Войдите в кабинет, нажмите колокольчик, включите уведомления и разрешите их браузеру.
Проверьте пробное уведомление. Сделайте это отдельно на каждом нужном устройстве
(до пяти браузеров на аккаунт). На iPhone/iPad с iOS/iPadOS 16.4+ сначала добавьте
сайт на экран «Домой» и запускайте с этого значка. При выходе из аккаунта подписка
этого браузера удаляется; сброс пароля удаляет все подписки аккаунта.

VPS, Cron, очередь и постоянный worker не нужны. Отправка выполняется сразу после
сохранения события, параллельно на подключённые устройства с тайм-аутом 5 секунд
для каждого запроса. Нужны HTTPS, PHP OpenSSL с P-256, curl и исходящий HTTPS к
push-службам браузеров. Поддерживаются FCM (Chrome), Mozilla, Apple и Windows Push.
Ошибки push не откатывают сообщения и оплаты; недействительные подписки удаляются.
Автоматических повторов отправки нет, доставка не гарантирована: проверяйте поддержку
и раздел чеков в кабинете. При большом числе администраторов отправка может увеличить
время HTTP-запроса; решение рассчитано на текущий небольшой кабинет поддержки.

В push нет ФИО, текста переписки и платёжных реквизитов. Адрес подписки и ключи
хранятся зашифрованными; полезная нагрузка зашифрована для браузера. Доставка идёт
через внешнюю push-службу браузера, что отражено в политике. Service worker не
кеширует личный кабинет и документы для офлайн-доступа.

### Бот НПД: получение оплат и возврат чеков

Бот вызывает конечные URL без перенаправлений:

- `GET https://лко-лкр.рф/api/npd/payments`
- `POST https://лко-лкр.рф/api/npd/receipts`

Оба метода требуют `Authorization: Bearer <NPD_BOT_SECRET>` и `Accept: application/json`.
POST также требует `Content-Type: application/json`. Сессия пользователя и CSRF-токен боту не нужны. Доступ по пустому ключу или ключу короче 32 символов закрыт; ключ администратора/ЮKassa не используется. Ответы не кэшируются. Ограничение — 60 запросов в минуту с одного IP.

Настройка на хостинге после загрузки обновления:

1. Выполните `/opt/php/8.4/bin/php artisan migrate --force`.
2. Сгенерируйте отдельный ключ: `/opt/php/8.4/bin/php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'`.
3. Запишите результат в серверный `.env` как `NPD_BOT_SECRET=...` и в настройку Bearer-ключа бота. Не публикуйте ключ.
4. Зафиксируйте границу новых оплат: `NPD_BOT_SINCE="2026-10-13T17:36:24+07:00"`. Граница включительная; не меняйте её при повторных развёртываниях.
5. Выполните `/opt/php/8.4/bin/php artisan config:cache` и, если маршруты закэшированы, `/opt/php/8.4/bin/php artisan route:cache`.
6. В боте укажите `payments_url` и `receipt_url` выше, а `shop_id` — ID рабочего магазина из `YOOKASSA_SHOP_ID`.

GET возвращает `{"payments": [...]}` либо `{"payments": []}`. Только реальные `succeeded` платежи в режиме `npd_manual`, без ранее прикреплённого чека. Время оплаты берётся из `captured_at` ответа ЮKassa, а не из времени webhook. Перед сохранением снимка сверяются ID магазина (`recipient.account_id`), ID заказа и платежа, статус, признак реальной оплаты, валюта и полная сумма. Источник полей: [официальная документация ЮKassa](https://yookassa.ru/developers/solutions-for-platforms/split-payments/payments).

Данные фиксируются в зашифрованном снимке и далее не меняются: `shop_id`, `payment_id`, `status`, `test`, `amount_kopecks`, `currency`, `paid_at` (ISO 8601 UTC), `description`, `buyer`. Описание — «Пакет из N генераций личных карточек ЛКО/ЛКР», где N берётся из оплаченного заказа. Физлицо передаётся как `{"type":"PERSON"}`, организация/ИП — `{"type":"COMPANY","inn":"...","name":"..."}`. Текущий тариф не влияет на ранее оплаченные заказы.

Обычная выдача ограничена 100 самыми старыми готовыми платежами. GET не помечает их обработанными. Для оплат между границей запуска и обновлением кода, а также записей без снимка, GET дополнительно проверяет до двух платежей через ЮKassa (таймаут каждого запроса 5 секунд). Поэтому при первом запуске очередь может заполняться постепенно. Ошибки проверки откладывают конкретную запись на 15 минут; другие платежи продолжают выдаваться. Новые подтверждения оплаты фиксируют снимок сразу из уже полученного сервером ответа ЮKassa.

POST принимает:

```json
{
  "shop_id": "123456",
  "payment_id": "yookassa-payment-id",
  "amount_kopecks": 89000,
  "currency": "RUB",
  "receipt_id": "id-from-fns",
  "receipt_url": "https://lknpd.nalog.ru/api/v1/receipt/242022368804/id-from-fns/print"
}
```

Платёж ищется по паре `shop_id` + `payment_id`, сумма и валюта сверяются со снимком. Ссылка должна соответствовать переданному ID чека и ИНН владельца из `SERVICE_OPERATOR_INN`. После транзакционного сохранения возвращается `204`; повтор того же результата также возвращает `204`. Другой чек, несовпадение суммы или повторное использование чека для другого платежа — `409`; некорректное тело — `422`; неизвестный платёж — `404`; неверный ключ — `401`. Другой чек не перезаписывается и при ручном прикреплении администратором. Письма не отправляются; ссылка показывается в существующей истории оплаты пользователя.

Проблемный платёж можно временно исключить, не заполняя всю очередь ошибками бота:

```bash
/opt/php/8.4/bin/php artisan npd:defer YOOKASSA_PAYMENT_ID --hours=24
```

Вернуть его в очередь: та же команда с `--hours=0`. Callback принимается и во время отсрочки: если бот уже создал чек, он сможет надёжно передать результат. Уже оформленные вручную платежи с сохранённой ссылкой/датой чека не попадают в выдачу. Крон и отдельный worker на хостинге не требуются.

### Вход по логину и повторяющиеся контактные email

Новые аккаунты регистрируются с уникальным логином (`username`): 3–40 символов, латинские буквы, цифры, точка, дефис, подчёркивание; первый символ — буква или цифра. Логины приводятся к нижнему регистру. Email больше не уникален. Аккаунты, их балансы и данные остаются независимыми.

У прежних пользователей логин остаётся пустым до выбора в обязательном окне кабинета. До этого можно войти по старому email; после выбора — только по логину. Действующие сессии не сбрасываются при миграции. Контактная почта по-прежнему используется для доставки писем. API входа и запроса восстановления принимает `identifier` (логин либо email старого аккаунта без логина); `POST /api/username` задаёт логин только текущему авторизованному аккаунту и только один раз.

Токены восстановления хранятся под ключом `account:ID`, а не общей почтой. Миграция переносит существующие токены, сохраняя срок действия. Новые ссылки содержат `account_id`; старые ссылки с email однозначно привязаны к прежнему владельцу через внутренний `legacy_email`. Изменение логина не меняет привязку токена. В письме указан логин, если он уже задан. Не меняйте `legacy_email` вручную.

Обновление на REG.RU следует проводить одновременно для бэкенда и фронтенда:

1. Сделайте резервную копию базы средствами хостинга.
2. В каталоге бэкенда включите обслуживание: `/opt/php/8.4/bin/php artisan down`.
3. Загрузите обновлённый бэкенд и содержимое `frontend/dist` в `public/app`.
4. Выполните `/opt/php/8.4/bin/php artisan migrate --force`.
5. Выполните `/opt/php/8.4/bin/php artisan config:cache`, `/opt/php/8.4/bin/php artisan route:cache` и `/opt/php/8.4/bin/php artisan view:clear`.
6. Выключите обслуживание: `/opt/php/8.4/bin/php artisan up`.

Не запускайте старый код регистрации во время удаления уникального индекса email. Откат миграции блокируется, если общая почта уже используется несколькими аккаунтами; записи автоматически не удаляются и не объединяются. Команды `support:admin` и `cards:demo` принимают логин; email принимается только при единственном совпадении, чтобы не выбрать другую организацию случайно.
